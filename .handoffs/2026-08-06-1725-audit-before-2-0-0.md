## Decisions made

- **2.0.0, not 1.1.0.** Exit codes, output format, and config precedence all
  changed. `breaking_always_bump_major = false` only applies below 1.0, so the
  `!` in the squash title is what produced a major.
- **MSRV stays at 1.89.0 for now.** Deferred deliberately; see
  `fleet-msrv-bump` in the release-stuff hub memory. An MSRV bump is itself
  breaking, so it wants the next major, and librebar has to lead.
- **`BITO_LOG_PATH` and `BITO_LOG_DIR` outrank `-c`.** Documented rather than
  changed. Config fields follow `-c` > `BITO_*`; log destination is
  operational and an operator has to redirect it without editing config.
- **The two remaining deny warnings stay.** They are real duplicates, both
  transitive, neither ours. Skipping them would rebuild the stale list that
  was just pruned from 20 entries to 3.

## Landmines

- **`bito analyze` does not enforce `--max-grade` or `--passive-max`.**
  Measured on `main` today: `readability --max-grade 5` exits 1, while
  `analyze --max-grade 5` and `analyze --passive-max 1` both exit **0** on the
  same failing document. Only `--style-min` gates. This is the audit's
  `analyze-thresholds-not-enforced`, and it is worse than a bug: `docs/UPGRADING.md`
  and the draft release notes both claim *every* threshold now sets the exit
  code in every format. That sentence is false for `analyze`. Fix the code or
  fix both documents, but do not ship them as they are.
- **The audit artifacts are immutable.** `README.md`, `report.html`,
  `findings.yaml`, `recon.yaml`, and `assets/` must not be edited.
  `actions-taken.md` is append-only and does not exist yet — create it with
  the first action, and keep the front-matter counts accurate
  (`open = 14 - everything else`).
- **`unset RUSTC_WRAPPER` in agent sessions.** `sccache` inherits the sandbox
  of whatever started it and will make `./target` unwritable for every cargo
  run on the machine. `RUSTC_WRAPPER=""` is not enough. Recover with
  `sccache --stop-server`.
- **`just check` reformats.** It runs `just fmt`, not `fmt --check`. Stage
  after running it, or CI's `cargo fmt --check` catches drift you cannot see
  locally. This has broken a release before.
- **`dist/` is gitignored.** The release prose and postcard live there and are
  not in version control. Do not expect them on another machine.
- **`CHANGELOG.md` is generated.** `git cliff` rebuilds it from commit
  subjects, so hand-written prose there dies at the next release. Behavior
  changes go in `docs/UPGRADING.md`; the pointer to it lives in
  `cliff.toml`'s header, which survives regeneration.
- **Integration tests need `-C <tempdir>` for environment work.** Config
  discovery walks up from the working directory and finds bito's own
  `.config/bito.yaml`, which supplies exactly the type information an
  `Option<T>` env-var test is trying to prove is missing. Two such tests
  passed against the broken librebar before this was caught.
- **A stale `dependabot/cargo/rmcp-1.4.0` branch exists.** rmcp 1.4.0 does not
  compile here — the `#[tool]` attribute changed shape. bito is on 1.8.0
  deliberately. Delete the branch rather than merging it.

## Conventions

- `cargo nextest run`, not `cargo test`.
- Never hand-edit a version in any `Cargo.toml`.
- Write `commit.txt`, stage the changes, and stop. Clay runs `gtxt`, which
  commits staged changes only.
- Merge with `git pm`. It takes the PR title from the last commit's subject
  and squashes; the repo disallows merge commits.
- No worktrees.
